# 我做了一个把 Markdown 变成「学习界面」的 Codex Skill

很多长文的问题，不是内容不好。

是打开那一刻，读者已经累了。

满屏 Markdown。

满屏段落。

满屏“你先读完再说”。

但真实情况是：

大多数人不是不想读。

是需要先知道：

这篇文章到底值不值得读。

所以我做了一个 Codex Skill：

**md2html**

它的作用很简单：

把一篇长 Markdown / 长文案，变成一个更适合学习的新知识界面。

不是普通的 Markdown 转 HTML。

而是：

- 先提炼中心命题
- 再做极简版导读
- 再做精炼版卡片
- 最后把全文折叠保留

读者先看懂结构，再决定要不要读全文。

---

## 这个 Skill 适合谁？

如果你经常处理这些东西：

- 长文案
- 公众号文章
- 产品说明
- 研究笔记
- 方法论文章
- 项目复盘
- AI 生成的长 Markdown

你大概率会用得上。

因为它解决的不是“排版”问题。

而是“理解入口”问题。

长文不应该一上来就要求别人读。

长文应该先给别人一个地图。

## 怎么安装？

仓库地址：

https://github.com/Yinmu/md2html

朋友只需要在终端里执行：

```bash
git clone https://github.com/Yinmu/md2html.git
mkdir -p ~/.codex/skills
cp -R md2html/md2html ~/.codex/skills/md2html
```

然后重启 Codex。

这样就装好了。

不用配置。

不用改代码。

不用理解里面怎么实现。

装完以后，它就是一个可以直接调用的 Skill。

---

## 怎么使用？

用法也只有一句话。

把你的长文交给 Codex，然后说：

```text
Use $md2html to turn this long Markdown article into an HTML learning interface.
```

如果你是中文使用，也可以直接说：

```text
使用 $md2html，把这篇长文变成一个适合学习的新知识界面。
```

它会生成一个单文件 HTML。

你可以直接用浏览器打开。

![使用方式](./assets/usage.png)

## 它会生成什么？

不是一篇更漂亮的长文。

而是一个“先看懂，再深入”的页面。

页面结构大概是这样：

1. 标题
2. 中心命题
3. 极简版 tab
4. 精炼版 tab
5. 折叠的完整正文

极简版适合快速扫。

每个章节只保留一句核心判断。

比如：

> AI 时代，最值钱的名片不是简历，而是可被看见和验证的作品。

精炼版适合多看一点。

每个章节会有：

- 标题
- 3 条要点
- 一句总结

如果想看原文，点卡片就能跳到对应段落。

看完以后，还可以点“回到图文导读”。

## 什么时候最有用？

我觉得有三个场景特别适合。

### 1. 长文发布前

你写完一篇很长的文章。

但你不确定别人能不能快速看懂。

这时候可以先用它生成一个视觉版。

如果视觉版都讲不清楚，说明原文结构可能也有问题。

### 2. 资料转述时

别人发你一篇很长的 Markdown。

你不想一段一段读。

先丢给这个 Skill。

它会帮你做一个可扫读的入口。

### 3. 分享给非技术朋友时

很多人不喜欢看 Markdown。

不是他们不认真。

只是 Markdown 对普通读者来说，信息密度太硬。

HTML 页面更接近“产品界面”。

读起来更自然。

---

## 我最喜欢的一点

它不是把长文变短。

而是把长文变得更容易进入。

这两个东西不一样。

“变短”可能会损失细节。

“更容易进入”是先给人一个抓手。

你可以先看极简版。

觉得有价值，再看精炼版。

还想确认，再展开全文。

这才是更符合人类阅读习惯的方式。
